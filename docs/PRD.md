> **版本**：v2.1 · **更新日期**：2026-10-20 · **状态**：已上线（Vercel 部署）

---

## 1. 产品概述

### 1.1 产品定位

**健康助手**是一个**纯前端运行**的 AI 营养健康决策助手。用户在浏览器中直接与 DeepSeek 大模型对话，获取基于本地知识库 + 联网搜索兜底的营养健康建议。所有会话数据存储在浏览器本地（IndexedDB + localStorage），无需后端服务器。

### 1.2 核心价值

| 价值 | 说明 |
|------|------|
| **零部署成本** | 静态托管到 Vercel 即可，无需服务器、数据库、后端代码 |
| **知识库内置** | 24 篇营养学文献（含《中国居民膳食营养素参考摄入量 2023 版》）预打包进前端，BM25 检索，完全离线 |
| **联网搜索兜底** | 本地知识库命中不足时自动调用 Tavily API 联网搜索，弥补知识盲区 |
| **用户画像驱动** | 回答结合用户个人情况（年龄/体重/目标等），个性化推荐 |
| **引用可溯源** | 每个回答附参考来源卡片，点击跳转到原始文献，标注证据等级 |
| **领域门控** | 非健康问题不触发 RAG 检索、不展示参考来源、不显示 AI 免责声明 |
| **结构化健康目标** | 目标打卡 + 连续天数 + 近 7 天点阵 + 到点提醒，执行进度注入 AI 上下文，数据不出设备 |
| **AI 主动跟进** | 建议后自动生成跟进问题，到期弹"小回访"收集反馈，反馈注入后续回答形成陪伴闭环 |

### 1.3 非目标

- 不做多用户 / 登录系统
- 不做知识库在线更新（更新需重新构建部署）
- 不做疾病诊断或开具处方
- 不做后端部署（纯前端 Demo 定位）
- 不做 API Key 运行时设置（Key 通过环境变量在构建时注入）

### 3.2 数据流

```
用户输入文本
  │
  ├─① 领域门控：isHealthRelated(text) ?
  │    YES → 进入检索流程
  │    NO  → 跳过 RAG，直接发给 DeepSeek（无参考来源、无免责声明）
  │
  ├─② 本地 BM25 检索：searcher.search(text, 5) → localSources
  │
  ├─③ 联网搜索兜底：searchWebIfNeeded(text, localSources)
  │    触发条件：Tavily key 已配置 && 健康相关 && (本地为空 || top1 分数 < 5)
  │    → webSources
  │
  ├─④ 合并来源：sources = [...localSources, ...webSources]
  │
  ├─⑤ 构建 system prompt：buildSystemPromptWithRag(画像, sources)
  │    → 注入用户画像 + RAG 知识上下文
  │
  ├─⑤' 并行预取陪伴上下文（提交时新鲜读取，随 requestParams 透传）：
  │    buildGoalContext()    → 「## 健康小目标」段（目标 + 打卡进度 + 连续天数）
  │    getFollowUpContext()  → 「## 跟进情况」段（待跟进 + 近 7 天反馈）
  │
  ├─⑥ 发送请求：onRequest({ message, webSources, goalContext, followUpContext })
  │    → NutriProvider.transformParams 再次检索本地 + 合并 webSources + 附加两段上下文
  │    → DeepSeek SSE 流式响应（有可执行建议时回答末尾输出【跟进】行）
  │
  ├─⑦ 流式渲染：XMarkdown 实时渲染 + 自动滚动跟随
  │
  └─⑧ 落库：assistant 消息（含 sources）存入 IndexedDB
       → 正则提取【跟进】行 → followUps 表 + 消息 followUp 字段（仅 success，仅一次）
       → 首轮对话自动生成标题（≤10 字）

打开页面
  │
  ├─ 到期小回访：listDuePending(today) → 最多 3 条 antd 通知（做到了/部分做到/还没有）
  │    → 反馈事务内同步更新 followUps 表 + 消息 followUp 字段 → 卡片实时刷新
  │
  └─ 健康小提醒：useGoalReminders 每 30s 检查（localStorage 按目标按天去重）
       → 应用内通知（含"打卡"按钮）+ 已授权时叠加浏览器系统通知
```

### 3.3 存储分层

| 存储层 | 技术 | 用途 | 容量 |
|--------|------|------|------|
| IndexedDB | Dexie v3 (`nutrihealth-demo`) | 会话/消息 + 健康目标/打卡 + 跟进记录 | 浏览器限制（通常 GB 级） |
| localStorage | 浏览器原生 | 用户画像 + 上次会话 ID + 提醒去重记录 | ~5MB |
| 静态 JSON | knowledge-bundle.json | 知识库（构建时打入 bundle） | ~88KB |

## 5. 检索架构（多路召回 + 阈值过滤）

### 5.1 多路召回

当前实现**两路召回**，结果按"本地优先 + 网络兜底"顺序合并：

```
用户查询
  │
  ├── 路 1：本地 BM25 知识库
  │   ChatShell.tsx:263-266  searcher.search(text, 5)
  │   → localSources (KnowledgeSource[])
  │
  └── 路 2：Tavily 联网搜索（条件触发）
      ChatShell.tsx:267  searchWebIfNeeded(text, localSources)
      → webSources (KnowledgeSource[])
      │
      └── 合并：NutriHealthProvider.ts:134
          const sources = [...localSources, ...webSources]
```

### 5.2 精排（Re-Ranking）

| 环节 | 位置 | 说明 |
|------|------|------|
| 本地 BM25 排序 | `bm25.ts:127-131` | `getScores` → 降序排列 → `score > 0` 过滤 → topK 截取 |
| Tavily 排序 | Tavily API 内部 | 返回结果自带 `score`（0~1），保留到 `KnowledgeSource.score` |
| 展示层去重 | `BubbleRole.tsx:38-44` | 按 `document_id` 去重，同一文档只展示一条 |

> **当前局限**：两路结果各排各的，按"本地在前、网络在后"固定顺序拼接，无跨路统一分数归一化和重排。BM25 分数（量级 0~30）与 Tavily 分数（量级 0~1）未做归一化。

### 5.3 阈值过滤

三层阈值门控，从粗到细：

| 阈值 | 位置 | 作用 |
|------|------|------|
| `HEALTH_KEYWORDS` 命中 | `NutriHealthProvider.ts:57-62` + `webSearch.ts:108` | **领域门控**：非健康问题直接跳过两路检索 |
| `score > 0` | `bm25.ts:129` | **BM25 粗筛**：丢弃 0 分文档（完全无词命中） |
| `MIN_LOCAL_SCORE = 5` | `webSearch.ts:17, 109-110` | **跨路门控**：本地 top1 ≥ 5 视为"知识库足够"，跳过联网搜索 |

跨路门控关键逻辑（`webSearch.ts:103-111`）：

```ts
export async function searchWebIfNeeded(query, localSources) {
  if (!tavilyEnabled()) return [];           // 无 key → 不搜
  if (!isHealthRelated(query)) return [];    // 非健康 → 不搜
  const topScore = localSources[0]?.score ?? 0;
  if (localSources.length > 0 && topScore >= MIN_LOCAL_SCORE) return [];  // 本地够 → 不搜
  return searchWeb(query);                   // 否则联网兜底
}
```

```
│ │ [今日打卡]  提醒 [18:30]  浏览器通知 [关]     │ │
│ └──────────────────────────────────────────────┘ │
│                                                    │
│ ▸ 已归档（1）                                      │
├────────────────────────────────────────────────────┤
│ 提醒在页面打开时生效；关闭页面后将无法提醒  [取消][完成] │
└────────────────────────────────────────────────────┘
```

- 入口：侧栏底部"健康目标"按钮（AimOutlined，位于"个人信息"左侧）
- 每次操作即时写 IndexedDB（区别于 ProfileModal 的草稿模式）
- 打卡按钮 toggle；近 7 天圆点点阵（打卡=渐变填充，今日描边）
- 浏览器通知 Switch 首次开启时请求 `Notification.requestPermission()`，拒绝后降级为仅应用内提醒并警告

### 10.7 小回访卡片（FollowUpCard）

```
┌──────────────────────────────────────────────────┐
│ 🔔 小回访  10/21 到期  [待跟进]                   │
│ 明晚饭后按建议散步 20 分钟，做到了回来告诉我一声？ │
│ [做到了] [部分做到] [还没有]  [补充说明（可选）]  │
└──────────────────────────────────────────────────┘
```

- 位置：assistant 消息 footer 中，位于参考来源卡片与免责声明之间
- 状态 Tag：待跟进（cyan）/ 已做到（success）/ 部分做到（warning）/ 还没做到（default）
- 反馈后按钮区替换为只读反馈摘要；刷新后从消息 followUp 字段恢复
- 到期未反馈时，打开页面弹"健康小回访"通知（最多 3 条），通知内可直接三档反馈

## 12. 部署方式

### 12.1 本地开发

```bash
npm install
npm run dev          # http://localhost:3000
```

### 12.2 知识库更新

```bash
# 编辑 data/knowledge/ 下的 Markdown 文件
npm run build:knowledge   # 重新生成 knowledge-bundle.json
```

### 12.3 线上部署（Vercel）

- **平台**：Vercel
- **生产分支**：`master-纯前端存储`
- **框架**：Next.js（自动检测）
- **配置文件**：`vercel.json`（`{ "framework": "nextjs" }`）
- **Root Directory**：项目根目录（无子目录）

### 12.4 环境变量

| 变量 | 说明 | 必填 |
|------|------|------|
| `NEXT_PUBLIC_DEEPSEEK_API_KEY` | DeepSeek API Key（构建时注入客户端 bundle） | 是 |
| `NEXT_PUBLIC_TAVILY_API_KEY` | Tavily 联网搜索 API Key（免费额度 1000 次/月） | 否 |

> **安全提示**：`NEXT_PUBLIC_` 前缀的变量会在构建时被打包进客户端 JS，任何访问网站的用户都能在 DevTools 中看到这些 Key。这是纯前端架构的固有取舍——如需保护 Key，需引入后端代理层。
